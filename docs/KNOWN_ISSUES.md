## Operational limits

One realtime worker owns a namespace. Durable generations fence former owners at SQL and atomic cache boundaries; actual competing/paused/killed processes are tested locally. This is recovery/fencing evidence, not horizontally distributed ticking. Periodic combat checkpoints can roll back about one second and expire after 24 hours. Queue region is a preference rather than measured latency; competitive/public-poker queues remain absent.

Metric snapshots retain bounded process totals for 48 hours after their latest flush. They do not represent a sliding 48-hour event counter. Scraping requires a separately configured token; no deployed scraper, durable event/error aggregation or alert delivery is supplied. Local mixed load is small and reports observed latencies, not production capacity. Missing/size-mismatched private bytes are reported without deleting their metadata; local offset inventories can revisit/skip changes until a later sweep. Production restore and schedules must be exercised on the deployed host.

Next's missing framework ESLint-plugin build warning remains nonblocking; the actual repository ESLint and TypeScript checks run separately. Large social/game handlers and some broadly typed SQL rows remain despite the added domain modules. Source is local/uncommitted in an unborn repository; publishing a prepared environment and confirming fresh restoration are separate actions.
