# Parallel implementation contract

Root monorepo dependencies, tsconfig paths and package manager are maintained by the coordinating agent. All code is strict TypeScript. Domain code may use `db` (postgres-js tagged SQL) and `orm` (Drizzle) from `@tell-aviv/database`; `getUser(id)` returns shared camelCase `User`. UUID identities. Auth exports `getSession(request): Promise<User|null>` and `handleAuth(path,method,request,input): Promise<Response|undefined>`. Cookie name `ta_session`; opaque token SHA256 digest stored in sessions. No application user ID is accepted as authentication.

Authenticated domain handlers export `handleSocial`, `handleClasses`, `handleGames`, `handleAdmin` as `ApiHandler` from shared. `path` excludes /api; matched handlers return plain data; unmatched return undefined; throw `ApiError` for expected errors. Route wrapper returns `{data: result}` or `{error: message}`. JSON input is Record<string,unknown>, validate with Zod. Mutation route wrapper checks Origin against request URL / configured APP_URL and requires JSON (except file upload route). No fetch action in render.

GET /api/me returns current User. GET /api/auth/status reports native-password login, development login and email-provider availability. POST /api/auth/register and /api/auth/login use canonical username/password credentials. Optional email verification, one-use recovery links/codes, recent-auth sensitive changes and opaque session management are documented in AUTHENTICATION.md. POST /api/auth/dev {username} is explicitly development-only and cannot impersonate native-password accounts; POST /api/auth/logout and /api/auth/logout-all remain supported. Public health only. Authenticated POST /api/profile updates only editable fields, never role/xp/id. Production disables dev login.

Each domain owns migrations in packages/database/migrations: 001 foundation/auth, 002 social, 003 classes/creator, 004 games/economy, 005 realtime. Migrations run in sorted order and recorded durably. Use snake_case DB fields, return documented camelCase or consistent raw records. Coordinate API shapes with web agent. Never private school resources in bootstrap/profile/game payloads.

Game client interface: `GameManifest` in games/registry.ts, `GameSDK` in packages/game-sdk/src/index.ts (constructor gameId; user(), load(), save(data,schemaVersion=1), action(action,payload), leaderboard(), presence(), start()/end()). Registry array `games` contains only playable implemented entries. React `GamePlayer` in games/GamePlayer.tsx accepts `{gameId:string}`. Games use SDK exclusively for platform services. Authoritative action endpoints for currency, incremental offline progress, casino rolls. Generic saves never set authoritative balances or award arbitrary achievements/scores. Competitive score submissions need server outcomes; casual browser-authoritative runs explicitly unranked.

Social agent owns packages/platform/src/social.ts and 002 migration. Classes/creator agent owns packages/platform/src/classes.ts, storage provider, 003 migration and web Classes/Creator components. Game backend agent owns packages/platform/src/games.ts, 004 migration and pure server simulations under games/server. Realtime agent owns apps/realtime, 005 migration and multiplayer protocol. Root owns auth/database foundation, root configs, integration tests/docs. Web agent owns app layouts/styles/pages and social UI. Game client agent owns game-sdk/runtime, registry, games client modules and GamePlayer.
