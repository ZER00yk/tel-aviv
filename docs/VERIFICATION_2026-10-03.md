## Major features implemented

- **Creator 2.0:** compatible schema-1/2 levels, 16 object types, typed variables, nested conditions, bounded deterministic event/action execution, visual reference-safe logic editing, undo, four playable templates, paged/filterable discovery and server-replayed, version-pinned completion records. Attempts accept inputs rather than claimed wins. Multiplayer, custom assets, collaborative autosave and fastest-time ranks remain absent.
- **Ego Trip:** 40-room/eight-district solo campaign, eight bosses, seven weapons and 23 modifiers while preserving original campaign/rush saves; server-owned 2–4-player campaign with shared route votes, personal rewards, helpers/shops/rests, revival, leader transfer and recovery; authoritative input-only solo ranked boss gauntlet with separate categories. Ranked and co-op cover defined subsets. A 45–60-minute pacing target has not been measured.
- **Classes:** semantic Markdown and bounded safe KaTeX, assignment planner/history/notes, editable flashcards with private chronological reviews/statistics, exact-set multiple-answer quizzes with versioned answer breakdowns and owner analytics, and once-only scheduled reminders. Existing private sharing checks remain in force.
- **Chat and presence:** named/followed/archived/paged threads and unread cursors; group name/avatar/member/owner management; private server emoji upload/insertion/live removal; a configured GIF adapter; explicit authorized HTTPS text previews with a constrained transport. Automatic idle aggregates tabs without overriding manual DND/Invisible. Opt-in desktop alerts honor preferences, foreground/Focus checks and cross-tab IndexedDB deduplication.
- **Multiplayer infrastructure:** durable SQL queue tickets, ready deadlines, cancellation/decline, party and block/feature eligibility, reconnect and partial-allocation recovery. SQL checkpoints recover actual killed workers and scoped Redis loss. Turn games and poker read committed SQL; periodic games preserve committed lifecycle transitions while retaining newer live simulation within the same match. One worker per namespace is enforced.
- **Velvet Casino:** fictional-credit offer/barter escrow with reserved collectible copies, idempotent settlement/history and live refresh; private 2–6-player Hold'em with hidden cards, betting streets, all-ins, side pots, ties, atomic stake/checkpoint persistence and once-only payout/refund. Tables use equal 100–10,000-Credit buy-ins and one hand per started match. No real-money flow exists.
- **Other game depth:** Neon Defense has three maps, ten enemy roles, four boss behaviors, tower combinations, bonus tiles, priorities, persisted campaign clears and bounded Endless; Paper Odyssey has 44 cards, ten functional relics, six events, more enemies and three bosses with passives/upgrades/removal; the shared board host supports local and authoritative Four in a Row, chess and forced-capture checkers.
- **Operations/admin/input:** bounded maintenance tasks, provider inventory/reconciliation/probes, durable cleanup retries, coordinated SQL/upload backups and guarded retention; leaderboard reset epochs and real category/period/friend filters; operational status and bounded per-process metrics; persisted movement remaps, validated gamepad/pause input and mobile touch/text/contrast/motion support. Development/build caches and browser outputs are isolated, and startup avoids duplicate servers.

## Notable bug and security fixes

- Creator pointer-up undo no longer dereferences cleared drag state; attempt sequencing/locking prevents forged or duplicated completion; views use the server-pinned level version; StrictMode starts once, sound toggles preserve a run, and explicit restart creates one new attempt.
- Multiplayer player views whitelist public identity/readiness/connection fields instead of spreading account settings, role or authentication fields into room snapshots. Hidden role, drawing, poker and private campaign state remains participant scoped.
- Match outcomes and checkpoints commit atomically, including empty-room deletion/refund. Failed checkpoint writes roll back outcomes. Committed terminal/new-match SQL state wins over stale Redis without overwriting newer same-match playing simulation on reads.
- Poker checkpoint/escrow writes are atomic, legacy result hashes tolerate only verified historical JSON ordering, and already-paid results survive account deletion/disable. Credits reset rejects an active escrow under the wallet lock; account erasure refunds unfinished reservations before removing a user.
- Thread/group permissions are rechecked under mutation locks. Private school resources, history, emoji and account exports require current authorization. KaTeX disallows trusted commands; user Markdown/HTML is escaped.
- Preview fetches require an explicitly selected stored room/message and authorization before and after transport. HTTPS/port/userinfo restrictions, all-answer public-address validation, pinned DNS/TLS host, redirect revalidation, total deadline and byte/compression bounds address SSRF and oversized/erroring responses. Tests cover permission revocation and private-target rejection.
- Creator/marketplace/search and existing media/socket routes have explicit atomic request budgets. Anonymous authentication still needs deployment-specific trusted source identity before a proxy-safe per-source limiter can be added.
- Cross-tab notification deduplication uses a transaction; storage binding/cleanup/backup locks prevent deletion races; missing bytes are reported without deleting private metadata. Reset epochs prevent stale cumulative saves or old server run identities from restoring reset leaderboard scopes.
- Ego's casual SDK save remains administratively resettable after ranked catalog support was enabled; resetting it preserves the separate authoritative ranked run.
- Held movement clears when bindings change; button-focused keys do not drive co-op; autorepeated Escape does not toggle pause repeatedly. Mobile search fits larger text and the close-navigation backdrop occupies the exposed area beside the drawer.
- Three existing browser flows now synchronize with a committed start and focus the game arena. The previous failures did not indicate missing gameplay or missing poker ledger writes; the corrected tests retain their real movement and exactly-once financial assertions.

## Backup, source artifact and reusable environment

The verified v2 snapshot is `/workspace/tell-aviv-backups/tell-aviv-2026-10-03T16-58-06-771Z-838e587f`: five checksummed uploads and a 260,863-byte SQL dump. Its isolated restore checks table/account/migration counts and each restored binary hash, then removes only its randomly named restore database/upload directory. Counts describe that snapshot, not permanent application sizing. [BACKUP_RESTORE](BACKUP_RESTORE.md) documents both compatibility and operational limits.

After code, tests and documentation are stable, `pnpm source:archive` creates a fresh archive outside the checkout. It excludes credentials, dependencies, private service/upload data, build caches and test output; compares the complete tar membership with the source list; and checks every archived file against its pre-archive SHA-256. The sibling `.manifest.json` contains all member hashes and the archive checksum; `.sha256` supports a separate `sha256sum -c` check. The handoff provides the actual path/checksum after this final step. Previous source archives remain intact. Putting the archive checksum inside its own source documentation would make it circular, so the checksum is stored in those sibling artifacts and the handoff.

Cloud onboarding `install_script` and `start_skill` are saved in draft revision 4. Frozen setup, service startup and repeated invocation work in this instance. The draft is not published, and a fresh-task snapshot restoration has not been exercised. OAuth/GIF/S3 production credentials, public DNS/TLS, Docker registry/image verification, off-host backups and deployed scheduler/load behavior are separate external prerequisites.
