## Authentication and HTTP security

Native username/password registration and login replace the Google requirement. Canonical lowercase usernames preserve the immutable account UUID; passwords accept 12–128 characters, at most 512 UTF-8 bytes, with significant whitespace. The native binding uses **Argon2id, 65,536 KiB (64 MiB), three passes, one lane and a 32-byte output** by default. Bounded configuration, four active hash jobs and 32 queued jobs limit password work; missing-account login verifies a dummy hash. `@node-rs/argon2` is externalized in Next production builds, and real hash-parameter checks passed.

Random 256-bit session tokens persist only as SHA-256 digests. Production cookies are Secure/HttpOnly/SameSite=Lax, with a 30-day expiry. Registration/login rotate sessions; malformed or ambiguous cookies, revoked/expired sessions and disabled/deleted accounts are rejected. Ten-minute recent proof is credential-version bound. Password/email/username changes, device revocation, recovery generation and deletion enforce it under transaction locks. Password changes revoke other sessions by default; explicitly retained sessions lose their recent proof. Development password conversion preserves UUID/data and rotates all old sessions; development login is unavailable in production and cannot claim native or historical external-only accounts.

Optional private email must be verified before password recovery. Twenty-minute reset/verification tokens are digested, credential-version bound and transactionally single use; replacement invalidates prior links. New links use URL fragments and are stripped from history before an explicit consume action. Eight random 128-bit recovery codes appear once and persist only as digests; regeneration/reset invalidates the older set. Concurrent token/code uses admit exactly one winner. Forgot-password responses are neutral, with a two-second response floor and abortable 1.5-second delivery deadline. Delivery runs in the request; there is no durable retry outbox claim.

The HTTPS Resend adapter and test-only transport boundary are implemented. **Live sender/domain/inbox delivery is unverified. Passkeys/WebAuthn, physical authenticators and verified-email login are not implemented.** Historical external-only accounts need a separately authorized ownership migration. The host-only first-owner script previews an existing native account and requires exact UUID confirmation, serializes competing attempts and writes an immutable audit once. Five real-PostgreSQL cases used isolated schemas; no real owner was promoted. See [authentication](AUTHENTICATION.md) and [owner bootstrap](BOOTSTRAP_OWNER.md).

Native mutations check the application origin, JSON MIME/object format and 16-KiB body limit. Durable shared 120/minute, identity-specific and attested-source 30/minute budgets charge before parsing/password work. Forged forwarding headers are ignored; only the configured constant-time proxy proof and one normalized IP establish source identity. The Caddy recipe overwrites those headers and keeps service ports private. Production responses use a fresh 128-bit nonce/strict-dynamic CSP, framing/base/form/object/MIME/device constraints and HSTS. Development uses a separate HMR-compatible policy. See [rate limits](HTTP_RATE_LIMITS.md) and [security](SECURITY.md); final local HTTPS results are recorded in the validation table, with public deployment still unverified.

The local production HTTPS fixture checked native login/Secure cookies, fresh navigation nonces and matching inline scripts, disabled development login, Creator saves, Ego canvas and Security controls. An actual Zod 4 optional JIT probe caused two script-source violations; the browser validation configuration now disables that probe before rendering. Strict nonce/strict-dynamic policy still omits unsafe-eval. The matching production build and rerun passed all eleven checks with zero CSP violations/page errors.

The focused native-auth checks passed 59 backend cases and six browser workflows, covering database races, versioned proof, fixation/revocation, whitespace/hash parameters, development conversion, recovery, provider timeout/failure, disabled/deleted accounts and private metadata. These are local implementation checks, not a complete production security audit.
